*Zainicjalizowany: 2026-06-06*

## Decyzje

### [D-1] 2026-06-06 — Sklepy w MVP
**Kontekst:** Brainstorming definiował MVP = 3Trolle + AlePlanszowki + Mepel. Raport techniczny potwierdził, że Mepel aktywnie blokuje boty (HTTP 403, Cloudflare AI Labyrinth).
**Decyzja:** Opcja B — MVP = 3Trolle + AlePlanszowki. Mepel → Faza 1.5 po pozytywnym teście Playwright.
**Podjął:** Kacper, 2026-06-06.

### [D-2] 2026-06-06 — Klucz deduplicacji produktów
**Kontekst:** Brainstorming zakładał EAN-first. Raport potwierdził, że EAN NIE jest w BGG API i może nie być w listingach sklepów.
**Decyzja:** BGG ID jako primary key deduplicacji. EAN zbierany lazily ze stron produktów jako dodatkowe pole.
**Uzasadnienie:** BGG ID jest zawsze dostępny przez API, stabilny i unikalny per edycja gry.

### [D-3] 2026-06-06 — BGG API wymaga rejestracji (od X 2025)
**Kontekst:** BGG XML API2 wymaga Bearer Token od października 2025. Licencja non-commercial dostępna (bezpłatna).
**Decyzja:** Rejestracja aplikacji w BGG jest pre-requisitem przed implementacją Paszportu Planszówki.
**Status:** OTWARTA — czy Kacper już zarejestrował? Wpływa na timeline.

### [D-4] 2026-06-06 — Stack techniczny (zatwierdzony przez raport)
**Kontekst:** Raport techniczny zweryfikował i zarekomendował konkretny stack.
**Decyzja:** Python 3.11 + Scrapy 2.14 / FastAPI / Next.js 14 App Router / PostgreSQL 16 / Docker Compose / Hetzner VPS (~€5-6/mies.)
**Uzasadnienie:** Sprawdzony dla e-commerce scraping, wystarczający dla hobby scale, jeden deweloper.
**Miejsce:** addendum.md (szczegóły techniczne nie należą do PRD).

### [D-5] 2026-06-06 — Architektura: Modular Monolith
**Kontekst:** Raport odradzał microservices dla hobby projektu jednego dewelopera.
**Decyzja:** Modular Monolith na Docker Compose (scraper + FastAPI + PostgreSQL na jednym VPS, Next.js na Vercel free).
**Miejsce:** addendum.md

### [D-6] 2026-06-06 — RODO/PKE 2024: double opt-in dla alertów email
**Kontekst:** Polska Ustawa PKE z listopada 2024 wzmocniła wymogi zgody dla komunikacji email.
**Decyzja:** Double opt-in obowiązkowy. Suppression list wymagana. Data minimization (tylko email + game_id + próg + token).

### [D-8] 2026-06-08 — Aktualizacja C-9 i A-5
**Kontekst:** Zmiana modelu infrastrukturalnego z Hetzner VPS na w pełni bezpłatny stos free-tier; upgrade frameworku z Next.js 14 na Next.js 16.
**Decyzja C-9:** Koszt infrastruktury MVP = €0/mies. (GitHub Actions + Neon free + Vercel Hobby free + Brevo free tier). Poprzedni target ≤ €10/mies. (Hetzner CX21 ~€4.50) zastąpiony.
**Decyzja A-5:** Next.js 16 App Router ISR zastępuje Next.js 14. Założenie rewalidacji (domyślnie 1 h) bez zmian.
**Podjął:** Kacper, 2026-06-08.
**Zakres zmian w prd.md:** §4.8 FR-20 (inline tag), §6.1 in-scope list, §8.3 C-9, §10 A-5.

### [D-9] 2026-06-10 — Review adversarialny: spójność RODO + korekta C-9
**Kontekst:** Przegląd adversarialny wykrył twarde sprzeczności RODO oraz błędne „rozwiązanie" Gap #7 w readiness report (osłabienie C-9 €0 → ≤€10 na podstawie nieaktualnego Addendum I/Hetzner).
**Decyzje:**
- **C-9 = €0/mies. operacyjnie** (potwierdza D-8). Zmiana na ≤€10 z readiness report **cofnięta**; Addendum I (Hetzner ~€5–6) oznaczone *superseded*; domena = koszt roczny poza targetem.
- **Przechowywanie email:** `price_alerts.email` i `email_suppressions.email` = **surowy** (join L-3); `consent_log` = **hash** (`email_hash`, `ip_hash`). `price_alerts` ma dodatkowo `email_hash` (dedup + guard retencji).
- **email_suppressions.reason:** dodano `global_optout` (nadpisywalny jak `user_request`); `hard_bounce`/`complaint` permanentne.
- **consent_log.action enum** ujednolicony w epikach (`opt_in_requested`/`opt_in_confirmed`/`suppressed`) — usunięto niespójne `subscribe_request`/`doi_confirmed`/`global_optout`.
- **Retencja consent_log** 5 lat: DELETE tylko gdy brak aktywnej subskrypcji dla `email_hash`.
- **DOI:** wysyłka Brevo awaited z obsługą błędu (koniec fire-and-forget). Webhook Brevo dopisuje `consent_log` (`suppressed`).
- **Nowe decyzje architektoniczne:** L-13 (breach 72h, art. 33/34), L-14 (DPA art. 28 + rejestr art. 30), L-15 (rezydencja EU art. 44–49), L-16 (cookies/analityka PKE).
- **Nowe constraints PRD:** C-11 (administrator danych), C-12 (rezydencja EU), C-13 (DPA/rejestr/breach), C-14 (cookies/analityka), C-15 (Privacy Policy/Regulamin/Cookie Policy — gate launch).
- **Nowa historyjka 6.9:** dokumenty prawne + `docs/GDPR_PROCEDURE.md`; blokuje przyjęcie pierwszej subskrypcji email.
**Pre-launch blocker:** tożsamość administratora danych (C-11) — osoba fizyczna czy podmiot (wpływ na odpowiedzialność).
**Podjął:** Kacper + review adversarialny, 2026-06-10.
